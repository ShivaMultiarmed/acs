# Что это?

Мини-СКУД - система контроля и управления доступом. 
Данный проект является прототипом реальной системы. Представляет собой RESTful приложение.

# Что делает?

На данный момент основной функцией программы является контроль входов и выходов с территорий,
указанных в базе данных. Сначала происходит идентификация пользователя, затем проверка ключа на 
наличие разрешения доступа к конкретному объекту. Далее, основываясь на заданной бизнес-логике
система принимает решение, пропускать пользователя или нет. Например, нельзя войти или выйти дважды.

# Как запустить?

Данный проект контейнеризирован и поэтому его можно собрать с помощью `docker compose`

```bash
cd /путь/к/корню/проекта
docker compose up -d
```

# REST API схема

`POST /interactions` - добавляет запись о взаимодействии с объектами

Требует заголовок `Authorization: Bearer <code>` и `json`-объект в качестве тела запроса с полями:
- `worker_id` - идентификатор сотрудника
- `object_id` - идентификатор объекта, к которому нужно получить доступ
- `type` - тип взаимодействия, например, `ENTER` или `EXIT`

Например, `worker_id=1&object_id=1&code=kRYc7tQZfSWKHvL4wpxPrA==`

В качестве ответа предоставляет `json`-объект с информацией о взаимодействии пользователя с 
объектом. Например:

Ответ со статусом 200
```json
{
  "id": 1,
  "worker_id": 1,
  "object_id": 1,
  "date_time": "2026-11-02T10:42:56",
  "interaction": "ENTER",
  "error": "NONE"
}
```

Ответ со статусом 403
```json
{
  "id": 2,
  "worker_id": 1,
  "object_id": 1,
  "date_time": "2026-11-02T10:43:32",
  "interaction": "ENTER",
  "error": "FORBIDDEN"
}
```

# Стек технологий

Проект написан на языке C++. В кодовой базе присутствует разделение на уровень обработки запросов,
уровень бизнес-логики и уровень доступа к данным.

В процессе написания проекта были задействованы:

- `Docker` - для контейнеризации программы и её портируемости
- `CMake` - для подключения зависимостей и сборки проекта 
- `cpp-httplib` - библиотека для хэндлинга HTTP-запросов и формирования ответов
- `libpqxx` - библиотека для обеспечения доступа к СУБД
- `PostgreSQL` - реляционная СУБД

Присутствуют таблицы:
- с данными пользователей
- с данными объектов (кабинетов, программ и т.д.)
- с разрешениями доступа конкретных пользователей к конкретным объектам
- с взаимодействиями пользователей с объектами
